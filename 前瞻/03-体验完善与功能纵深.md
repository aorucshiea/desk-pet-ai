## A. TTS（语音合成）

**现状**：凌凌纯文字气泡，无任何音频输出。grep 无 TTS/tts 相关模块。

**本地优先的方案空间**：
- **轻量**：Piper（CPU 可跑、中文音色有、体积几十 MB）
- **高质量情感**：IndexTTS / GPT-SoVITS / CosyVoice / F5-TTS（可声音克隆，较重，需要 GPU 才好体验）
- 云端（edge-tts 等）违反 local-first，只作可选项

**架构建议（与 sidecar 家族同构）**：独立 `tts-server` 进程，gateway 管理（先例：`omniparser_manager.py` / `llama_client.py`）。**默认静音**，音频权限进设置。

**与本项目其余系统的接缝**（这才是"凌凌的 TTS"和普通 TTS 的区别）：
1. `think_filter` 的 delta 流按句切片 → TTS 队列逐句合成 → **边说边播**（不等整段）
2. `[EMOTION:]` 标签同时驱动**语调/语速**——情绪系统的第二输出通道（第一个是温度）
3. 说话冲动（organ_impulse）开口时先出声音，气泡跟上

## B. ASR（语音识别）

**现状**：零代码。

**方案空间**：`whisper.cpp`（llama.cpp 同门 GGUF，与 `llama_client` 子进程模式完全同构）/ sherpa-onnx（流式 + KWS 唤醒词）/ FunASR（中文最强）。中文场景下 FunASR/sherpa 优先考虑。

**交互分层**：**push-to-talk 先行**（长按说话，最诚实、无误唤醒）→ 唤醒词「凌凌」后置（KWS 常开有麦克风隐私含义，走屏幕 consent 同款三态门控）。

**联动**：识别文本进气泡输入框；用户开口 → organ_impulse 冷场计数清零（潜意识的听觉）。

## C. 情绪→温度调控（已接线，性质=验证+遥测）

## F. 设置页信息架构

**现状**：20 个分区 tab、renderer 约 1.7 万行（已模块化到 `settings-tab-*.js`），搜索已上线（27b1020）。

**重组原则（草案）**：按**用户任务**而非子系统分组——「第一次用」（模型/引擎）→「它怎么活」（情绪/记忆/进化）→「它怎么动」（外观/动画/世界）→「它怎么连」（MCP/远程/移动端）→「高级」。高级项默认折叠；Vision 级实验功能收进单独分区并在描述里链到本目录对应文档。

**归属**：Qoder 地盘，方案需 Qoder 认可后动手。

## G. MCP / skill / 记忆系统的深入验证

**现状**：MCP（`mcp_manager.py`，5 轮工具循环上限）、skills（gateway 内置 writing/screen/coding/analysis + 顶层 skills/）、记忆（14 模块）机制俱在，但 **319 个 pytest 全是模块级单测**，chat 管线端到端零覆盖（B-11 实证过两起静默失效事故）。

**建议的验证 harness 三层**：
1. **golden prompt 测试**：mock provider，断言最终 system prompt 的段落顺序与内容（依赖 B-6 现状可先覆盖网关侧注入段）
2. **SSE 契约测试**：mock 流断言事件序列（start/delta/think/next_chat/end）+ 控制标签剥离行为
3. **行为遥测**：内存计数器 + `/api/memory/stats`（闪现率/recall 成功率/共鸣命中率/情绪轨迹），web-panel 出「凌凌心理报告」诊断卡——遥测本身也是产品功能

**此节是我（Kimi）认领意向**：B-10/B-11 正是无人认领且改测试不占任何地盘的活。`PET_MEMORY_DIR=<throwaway>` 纪律已内化。

## I. 模型自进化闭环：受控实验

**链路完整性**（代码层面已通）：`pet_forge_plugin` → 热加载（5s 轮询）→ 下轮对话可调新工具 → 改坏自动回滚。

**没做过的**：端到端**实测**——让凌凌真的自己长一个器官出来。实验设计（安全第一）：
- **必须在 throwaway 记忆目录做**（`PET_MEMORY_DIR=<隔离路径>`，活体记忆不许参与实验）
- 由一个剧本驱动：用户请求一个插件不存在的小能力 → 观察模型是否选择 forge → 插件质量 → 回滚路径演练
- 产出：成功率、失败模式分类、forge prompt 的改进点
