# 05 · 动画系统统一架构：GIF / Live2D / 3D 三后端 + 官方新主题

- **状态**：草案 v1（2026-09-30，机长已拍「先把动画系统搞好」＝**当前最高优先级**）
- **提出**：机长（2026-09-30）；**设计**：Kimi（k3）

> **机长指令原话**：先把动画系统搞好。先不删 MiniCPM 的主题，自己建一个，支持 Live2D 和 3D 以及 GIF（现在的）。我之前看到似乎有办法从 GIF 动画中提取骨架，这个提取的骨架能用吗？——问题在于即使提取骨架，模型的动作输出可能也不像人。

---

## 1. 先回答：GIF 提取的骨架能用吗

**结论：作为生产管线不成立，作为参考素材可以。** 逐层钉：

1. **GIF 是烘焙位图**。骨骼信息在逐帧渲成像素时已经不可逆丢失——「提取骨架」实际是**逐帧 2D 姿态估计**（OpenPose/MediaPipe/MMPose 系）+ 轨迹拟合。
2. **姿态估计的训练域是真人视频**。凌凌现有主题是 320px / 10fps 的像素机器猫与水滴生物——域差距下关节点输出基本是噪声，非人形角色干脆没有对应关节定义。
3. **姿态轨迹 ≠ 骨架绑定**。拿到轨迹也只有运动数据：没有部件分层、没有蒙皮权重、没有形变参数，无法驱动新角色；重定向还要再解一次体型迁移。
4. **机长的直觉命中更本质的一层**：即使轨迹干净，直接播放也是提线木偶——真实感不来自轨迹数据，来自**次级运动**（预备 anticipation、跟随 follow-through、挤压拉伸 squash&stretch、惯性、呼吸），而这些恰恰是姿态轨迹里最缺的东西。所以「不像人」不是提取质量问题，是**数据驱动播放的结构性缺失**。

**定案**：现有 GIF 保留为降级后端与「一次性复杂动作」通道（anim-engine 的 H3 管线继续承担）；新系统的动作真实感由**程序性次级运动**提供（见 §4），不追求从旧资产逆向。

## 2. 三后端统一架构

```
神经系统（01 文档 L2/L1）
   organ_body / organ_embody / Laya
        │  抽象运动语义（与渲染技术无关）：
        │  state: idle/walk/sit/scared…
        │  params: energy 0-1, valence -1..1, arousal 0-3,
        │          gaze(x,y), squash, breathing…
─────────▼──────────────────────────────────────
AnimationBackend 接口（Electron 渲染进程内，新增模块）
  load(theme) / setState(name) / setParam(k,v) / tick(dt) / dispose()
─────────┬──────────────┬──────────────┬──────
   GifBackend      Live2DBackend      ThreeDBackend
  （现有 GIF      （pixi.js +        （three.js +
   状态机收编）     pixi-live2d-display） three-vrm）
```

**语义层是关键设计**：上层只产出与渲染技术无关的运动语义；每个后端把语义映射到自己的兑现方式——

| 语义 | GifBackend（降级兑现） | Live2DBackend | ThreeDBackend |
|---|---|---|---|
| `state: scared` | 切 surprised GIF | 播 motion3.json + 表情参数 | 动画剪辑 + blendshape |
| `energy 0.8` | 切更高能量档 GIF（若有） | 动作速度/幅度参数线性放大 | 动画 timeScale + 姿态增益 |
| `gaze(x,y)` | 不支持（忽略） | ParamEyeBallX/Y + 头部跟随 | 眼骨/头骨 IK |
| `squash` 着地挤压 | 无（静态承受） | 体干 SD 参数 | 骨骼压缩 + 弹簧 |

GIF 后端兑现不了的一律**忽略不报错**——降级是设计行为，不是异常。

**Live2D 许可待办**：Cubism SDK 发行许可是独立条款（小体量免费、超阈值收费），出包前必须核对——挂账 99 清单。

**GPU 风险**：Live2D/3D 后端都走 WebGL，Electron 透明分层窗口 + WebGL 合成在 Windows 上有前科（clawd AGENTS.md 的 Do-Not-Revisit 教训）——**A1 动工前先跑最小 WebGL 透明窗帧率 spike**（挂账 99 清单，与 01 的 F1-5 合并）。

## 4. 动作真实感从哪来（回应「不像人」）

**程序性次级运动层**（脊髓层固有职责，不依赖任何模型）：

1. **弹簧-阻尼系统**：所有参数变化走二阶弹簧（不过冲的临界阻尼打底，情绪调制过冲量）——一个常数表就能让一切动起来"有重量"
2. **呼吸基线**：idle 状态下胸腔/身体的正弦微动 + 随机眨眼计时器（无需任何输入，永远活着）
3. **预备-跟随**：任何状态切换插 80–150ms 反向预备帧；动作结束部位依次止住（尾巴最后停）
4. **squash & stretch**：速度越大拉伸越甚，着地压缩回弹
5. **情绪调制参数形状**：valence/arousal 直接改弹簧刚度与幅度——「开心时蹦蹦跳跳」不是播不同的动画，是同一组动作在**不同物理参数**下呈现

Live2D 的连续参数系统与这套调制是**天作之合**（它的参数本来就是连续的）；GIF 后端享受不到——这正是「灵动」与「现状」的分界线。

## 5. 官方新主题（不动 MiniCPM 系，另起）

- **名称/目录**：`themes/deskpet/`（新），minicpm 残留主题不删（机长指令）
- **首发引擎：Live2D**。理由：与现有 2D 美术风格连续；参数系统天然承接情绪调制；资产工作流 = 立绘拆件（可借 anim-engine 的 Qwen-Image 透明拆件管线量产草件）+ Cubism Editor 绑骨（一次性人工投入）
- **VRM 第二形态**：同一角色设定出 VRM 版（VRoid 快速成型），接 ThreeDBackend
- **GIF 兜底**：同一角色的基础状态 GIF 集（anim-engine 管线现成）——新主题三后端齐备，旧主题（minicpm/cybercat/zero 等）自然退到 GIF-only，行为不变
