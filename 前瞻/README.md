# 前瞻（Foresight）

> 这个目录收录**尚未拍板的方向性构想与设计草案**。性质是「探索存档」，不是承诺、不是排期。
> 与 `docs/` 的分工：`docs/` 记录已存在系统的开发/调试/架构事实；「前瞻」记录**还不存在的东西该怎么长出来**。

## 写作规范

- 想法一律保留**提出者原话**（注明提出人与日期），整理者展开的部分另起段落，两者不混。
- 每篇开头标注状态：`草案` / `待拍板` / `已拍板` / `已落地`（落地后把要点迁回 `docs/` 并从目录移除）。
- 设计必须写明与现有工程的咬合点（具体文件/模块）与**待实测清单**——拍脑袋的内容单独标注，不与事实混淆。
- 可逆性审查是每篇的固定栏目：这个想法改坏了怎么退回来。
